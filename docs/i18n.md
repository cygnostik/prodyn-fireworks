# Instrument localization

AFTERLIGHT supports English (`en`) and Mexico / LATAM Spanish (`es-MX`). Translation is local, explicit, and bundled; no translation service, account, or network request is used.

## Preference contract

The instrument imports `getLanguage` and `setLanguage` from `public/language.js`. That shared module owns browser-language detection, the remembered `afterlight:language:v1` preference, and the `afterlight:language` window event. The menu’s native, labeled language select offers **English** and **Español**. Its option labels never translate. Changing language updates the document `lang`, visible controls, accessible names, selected effect, palettes, composer, preset cards, retained status/toast, and PWA guidance in place.

The language event only rerenders copy and layout. It does not recreate the renderer or audio context, alter the player clock, restart a finale, change effects/palettes, save a show, or clear the sky. All existing show IDs, palette IDs, densities, durations, file names, JSON schema, and share encoding remain unchanged. New default/preset titles use the current language; existing authored, saved, imported, or shared titles remain literal user data and are never retranslated on a language switch.

## Implementation

- `src/i18n-data.js`: explicit Spanish copy, including every catalog effect’s name and description, six banks, eleven palettes, three presets, settings/help, composer, errors, and all current PWA status/instruction source strings. Technical names such as Kamuro, Nishiki and Crossette are retained where appropriate.
- `src/i18n.js`: pure translation and literal substitution, HTML escaping, external-error adaptation, and static text/attribute bindings. Exact English source strings are stable lookup keys. PWA status plus retained installation guidance are translated segment by segment. Validation messages with layer numbers are mapped without changing validation logic.
- `src/main.js`: locale-aware dynamic rendering and subscriptions to the shared preference event. Transient messages retain their source and lazy translated arguments, so a visible message can switch languages too.
- `index.html`: native language select using the existing settings styles; redundant portrait intro removed completely. The approved English footer quote, creator/host credits, and brand lettering remain intact. The no-JavaScript fallback contains both languages because automatic detection requires JavaScript. Runtime metadata is translated; the authored JSON-LD stays English.

Static bindings retain individual text nodes instead of replacing containing markup, preserving inline keyboard hints, emphasis, controls, and icons. Dynamic template strings use escaped dictionary output. User titles enter only input values or text content; they never enter `innerHTML`. Unknown browser-generated diagnostics retain their original English diagnostic in English and use localized actionable fallback copy in Spanish rather than pretending to translate arbitrary engine text.

## Extending copy

1. Add an explicit English-source → Spanish entry to `messages`. Keep placeholders such as `{name}` and `{count}` identical between languages.
2. For static HTML, keep text in individual text nodes and bind before icons or dynamic UI replace those nodes. Brand/footer and script/noscript text are intentionally excluded.
3. For dynamic text use `t`, `h` (HTML-escaped translation), or `setCopy`/`toast` for retained transient messages. Use lazy argument functions when the argument itself must translate again on language changes.
4. Add every new effect to `effectTranslations` under its existing ID. Never translate IDs or change the catalog’s engine data.
5. If the PWA module adds/changes an English message, update the matching dictionary source entry. Its state and scheduling remain owned by the PWA module.

## Targeted checks

- `node --test tests/i18n-app.test.mjs tests/show.test.mjs`: dictionary coverage, literal/escaped interpolation, composed PWA messages, validation mapping and existing serialization/player checks.
- `npx playwright test tests/i18n-app.spec.mjs`: Spanish autodetection; accessible remembered manual override; all forty effect pads/descriptions/tooltips; unchanged quote; live finale/sound/data preservation; safe user text; translated validation, toasts, install guidance and confirmations; narrow-phone settings/composer interaction.

The parent workflow owns the production build, full browser gate, service-worker/offline release verification, and portrait spacing/CSS. These targeted checks do not establish physical iPhone Safari audio behavior, native installation prompt translation (browser-owned), or a fix for the separate iPhone WebAudio issue.
